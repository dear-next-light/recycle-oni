# リサイクルの鬼 / RECYCLE ONI v0.1.8

「まだ使える。」小鬼と施設を配置し、焼却される前の資源を救い出す、8Waveの物流ローグライト。HTML / CSS / Vanilla JavaScript / Canvas 2D製。外部通信・ゲーム用依存パッケージ・バックエンド・ログインは不要です。Sail Bike Runから独立したプロジェクトです。

## 一般公開版

- プレイ：https://recycle-oni.pages.dev/
- ソース：https://github.com/dear-next-light/recycle-oni
- Cloudflare Pagesの直接アップロード方式です。GitHubへの変更は自動配信されません。更新時は `dist/` を再アップロードしてください。

## 起動

Node.js 18以上で、このフォルダ内から `node server.mjs` を実行し、ブラウザで `http://127.0.0.1:4187` を開いてください。停止は Ctrl+C。依存パッケージのインストールは不要です。

`dist/` を静的Webホスティングに置けばURLで遊べます。ES Modulesを使うため、HTMLの直接ダブルクリックではなくHTTPサーバーで開いてください。Cloudflare Pagesへ `dist/` を直接アップロードして公開できます。GitHubリポジトリは https://github.com/dear-next-light/recycle-oni です。

## 操作

- オープニング画像の「ブラウザで今すぐプレイ」で準備開始。「Wave 開始」で収集車が動きます。
- 小鬼は自動で回収・運搬。施設が処理して利益になります。
- 準備中、下の施設ボタンを押して、盤面の「＋」が付いた空き建設区画をタップすると購入・配置します。建設区画は2×2マスの基礎で、歩道や区画の間には建てられません。資金不足、使用中・未開放の区画、配置の取消では購入されません。
- 施設をタップして「移動・入れ替え」を押し、移動先の建設区画をタップ。空き区画へ移動でき、使用中なら2施設を無料で入れ替えます。全区画が満員でも入れ替え可能です。施設のレベル・在庫・担当小鬼はそれぞれの施設に引き継がれ、同じ詳細画面からレベルアップできます。
- 小鬼をタップすると得意・特性・体力が見えます。準備中は担当施設を選び直せます。重なった小鬼をタップすると候補一覧を表示します。「小鬼一覧 / Oni roster」や施設の「担当小鬼」からも個別に選べます。
- 1施設の担当小鬼は2体までです。開始時は2施設・3体で1枠だけ空いており、5体目以降を雇うには施設を増やす必要があります。満員施設への担当変更はできません。
- 下部の操作列は横スクロールできます。小鬼追加は最大20体。開始時は5建設区画のうち2区画を使用し、残り3区画に増設できます。「土地拡張 ¥260」で、鍵の付いた下段5区画を開放し、合計10区画になります。準備中は盤面上の帯で使用数・空き区画・拡張費用を確認できます。
- 全区画が使用中でも施設ボタンを押すと、建てられない理由を表示します。拡張前は土地拡張と不足額を案内し、拡張後の10区画が満員なら強化・入れ替えを案内します。土地拡張と施設購入は別の支払いです。
- 初回は図解ガイドが開始・運搬・洗浄・圧縮・利益・号令・強化・増設を案内します。スキップ可能で、上部の「? ガイド」から再表示できます。
- 各Wave後の3択から1個無料で獲得し、次の回収ルートに備えます。最終Wave後は結果へ進みます。
- 「まだ使える！」は1Wave1回、6秒の移動・作業加速。
- 「音 OFF / ON」でミュート切り替え。初期状態はミュートです。
- スマホは縦・横どちらでも遊べます。ピンチまたは＋／−で100〜400%に拡大・縮小、ドラッグで盤面を移動、「全体 / Fit」で全体表示に戻ります。PCはホイールにも対応します。UIは日本語の下に英語を併記します。
- タイトルと結果画面の「他にもおもしろいゲームあるよ！ポータルサイトDearNextLightへ」から、[DearNextLight](https://dear-next-light.pages.dev/)を別タブで開けます。英語表記は「More games! Visit DearNextLight」です。

## 物流とバランス

施設は2×2マスの障害物で、入口は左上の1マス上。建設位置は見えている基礎区画と一致し、区画間の歩道を確保します。区画の数によって拡張前5施設・拡張後10施設が自然に収まり、歩道へ詰めて増設することはできません。小鬼はグリッドの幅優先探索で最短経路を歩きます。近い施設は回収・中間工程の運搬が短くなります。

PET・缶は洗浄→圧縮。スマホは到着時に修理施設があれば修理、なければ分解施設に向かいます。修理ルートの方が高利益です。処理済みの中間品は出力待ちになり、次工程の担当小鬼が運びます。施設内の待機品はWave間も残ります。

得意施設は処理速度+25%。ランダム特性は俊足・タフ・暑さ耐性・几帳面。体力の低い小鬼は減速し、自動休憩します。洗浄＋圧縮、修理＋分解はマンハッタン距離5以下で処理+10%。

回収できず道路を出たごみが焼却され、地球の熱が上昇します。v0.1.8では焼却熱の係数を0.30から0.55へ変更し、同じごみ・同じ強化状態で焼却した際の加算熱を約1.83倍にしました。25以上で回復低下、50以上で消耗増加、75以上でさらに消耗増加。熱に応じて猛暑・豪雨・嵐の確率が増えます。熱100で失敗。Wave回収率75%以上で熱を4下げます。熱はゲーム用の指標で、実際の排出量ではありません。

ランは実時間でおよそ9〜10分＋準備時間です。投入は各Wave45秒まで、最後の収集車が退出してから準備へ。HUDが0秒になっても到着済みの車両の処理を待ちます。高密度になると新規投入数を減らし、アクティブなごみ72個・収集車3台を守ります。Wave6〜8の1台あたり積載量は18・23・29個です。

利益は処理売上の累計、資金は初期資金＋利益−購入額です。焼却回避率は救出数÷投入数。結果の救出数には最終時点の未処理在庫も含まれます。処理完了率は最終工程を終えた個数÷投入数。高利益で低回収率を相殺できないよう、8Wave完走に加え、以下の4条件をすべて満たした最高ランクを採用します。完走失敗またはBの条件未達はCです。

| ランク | 焼却回避率 | 処理完了率 | 最終熱 | 総利益 |
|---|---:|---:|---:|---:|
| S | 90%以上 | 85%以上 | 15以下 | ¥25,000以上 |
| A | 80%以上 | 75%以上 | 35以下 | ¥18,000以上 |
| B | 65%以上 | 60%以上 | 60以下 | ¥10,000以上 |

## 購入価格と成長

初期資金は¥420。施設と小鬼の追加費用は購入前の総数に応じて段階的に上がり、購入ボタンには次の価格を表示します。新しい施設や増員と、既存施設の強化への配分を後半も選び続ける設計です。

| 購入 | v0.1.8の価格 |
|---|---|
| 施設 | 基準価格は洗浄¥150・分解¥170・修理¥180・圧縮¥150・堆肥¥130。3棟目の追加料金は¥0、4棟目は＋¥60、5棟目は＋¥150と増加し、10棟目は＋¥1,050。追加料金は施設の種類にかかわらず総施設数で決まります。 |
| 小鬼 | 4体目¥180、5体目¥200、6体目¥230と増加し、20体目は¥1,700。全体上限20体・1施設2体は維持します。 |
| 施設レベル | Lv.1→2は¥180、Lv.2→3は¥650、Lv.3→4は¥2,200。最大Lv.4で、担当小鬼の定員は増えません。 |
| 土地拡張 | 1回¥260で建設区画を5から10へ増加します。 |

施設の追加料金は `45d + 15d²`（`d = max(0, 現在の施設数 − 2)`）、小鬼は `180 + 15d + 5d²`（`d = max(0, 現在の小鬼数 − 3)`）です。購入が成立した時だけ引き落とし、取消や無効な操作で資金は減りません。

背景・施設の静的レイヤーのキャッシュ、HUDの変更時更新、描画解像度の制限などの最適化は維持しています。小鬼20体・アクティブなごみ72個・収集車3台の上限も維持します。一般的なスマートフォン実機での性能は未検証で、フレームレートや応答時間の実測値は記載していません。

## ファイル構成

- `dist/index.html`：画面の構造
- `dist/style.css`：HUD、メニュー、レスポンシブ表示
- `dist/config.js`：ごみ・施設・特性・強化・Wave・天候・価格・速度などの調整値
- `dist/economy.js`：総数に応じた施設・小鬼の追加価格と施設レベル費用
- `dist/plots.js`：見える建設区画・土地拡張・区画のタップ判定
- `dist/engine.js`：状態遷移、経路探索、物流、利益・熱・体力計算
- `dist/render.js`：Canvasの地形・施設・小鬼・車両・短い再利用演出
- `dist/audio.js`：Web Audioによる軽量な1ループBGMとSE（音声ダウンロードなし）
- `dist/app.js`：UI操作、音量設定とベスト記録の保存
- `dist/camera.js`：拡大・移動・ピンチ操作と座標変換
- `dist/labels.js`：英語併記
- `server.mjs`：ローカル確認用静的サーバー
- `tests/simulation.mjs`：ロジックの回帰検証
- `tests/economy.mjs`：価格の段階増加、購入額と失敗時の資金保全
- `tests/plots.mjs`：区画・歩道・拡張の配置判定と満員時の無料入れ替え
- `tests/expert-balance.mjs`：通常の収益と合法な操作だけでS判定へ到達する再現例
- `tests/browser.cjs`：ブラウザの8Wave通し・画面サイズ・保存検証

## バランス変更・素材差し替え

基本値は `dist/config.js` の `C`、`trashTypes`、`facilityTypes`、`traits`、`upgrades`、`waveDefinitions`、`weatherEffects` を編集します。現在の施設・小鬼の追加費用とレベルアップ費用は `dist/economy.js`、建設区画は `dist/plots.js` を編集します。強化の効果計算は `engine.js` の `speed`、`rate`、`heatEffect`、`sale`、`burn` に集約しています。

素材は dist/assets/ のWebPです。背景・5施設・5色の小鬼・トラックを独立描画し、施設座標・入口・当たり判定は維持しています。制作方針は ART-DIRECTION.md を参照してください。

## 保存

localStorageキーは `recycle-oni-v01`。ベスト利益・回避率・FLOW・ランク・ミュート設定を保存。旧判定のランクはv0.1.7でリセットし、その他の記録は引き継ぎます。図解ガイドの完了状態は `recycle-oni-guide-v1` に保存。進行中ランは保存しません。保存を拒否するブラウザでもプレイできます。

## 検証

`npm test` で現在のNode.js検証一式を実行します。自然な収益・購入での10乱数比較、価格、区画、人数・ごみ・車両の上限、資源保存、S到達の再現例を含みます。

`node tests/camera.mjs` でズーム・パン・ピンチ・タップ誤判定防止を検証します。

`node tests/simulation.mjs` で再現可能な8Waveラン、配置距離、得意差、熱、強化、敗北、再挑戦を検証します。

保存済みの `tests/browser.cjs` は旧版向けのブラウザ自動検証補助です。実行には開発用のPlaywrightとEdgeが必要で、ゲーム本体には不要です。Playwrightへのパスを環境変数 `PLAYWRIGHT_PATH` に指定して実行します。テスト時のみレスポンスへ検証用フックを追加し、同じゲームロジックの時間を進めています。製品ファイルにテスト用グローバルAPIはありません。現行版のブラウザ操作・表示の確認結果と検証条件は `TEST-REPORT.md` を参照してください。

## v0.1.2 ビジュアル更新

街並みと道路、5色の工場・小鬼、積載トラックをWebP化。HUD、熱ゲージ、色別ルート、FLOWの軽い光、号令の顔付き演出を追加しました。ゲーム計算・Wave・能力・価格は変更していません。

背景と施設は別Canvasへキャッシュし、変更時だけ再描画します。HUDは値の変化時だけ更新。使用素材を遅延ロードし、バージョン付き画像名と `_headers` で長期キャッシュします。画像12点合計約0.56MB、配布全体約0.63MB。高容量BGMや外部ライブラリは追加していません。

`node tests/visual-server.mjs` で開発用確認画面（4188番）を起動できます。QAボタンは検証サーバーだけが挿入し、配布する `dist/` には入りません。8Waveの加速確認、5施設の表示確認、10秒の描画測定に使用します。公開するのは `dist/` のみです。

## v0.1.6 施設ごとの小鬼定員

各施設の担当上限を2体に設定しました。増員ボタンには現在人数と全施設の合計枠を表示し、全施設が満員なら無効になります。施設詳細には担当数を `1/2` の形式で表示。担当変更では満員施設を選択できません。施設レベルでは定員は増えないため、増員には新しい施設の建設が必要です。全体上限12体は維持しています。

## v0.1.7 図解ガイド・後半の成長・厳格な判定

初回の序盤にアイコンの工程図、実際の対象を囲む枠・矢印を表示します。プレイを止めず、購入や号令を強制しません。短い日本語・英語、スキップ・再表示、動きを減らす設定に対応します。タイトルにもDear Next Lightへのリンクボタンを追加しました。

1施設2体を維持し、全体20体へ増加。Wave1〜5の積載量は維持し、6〜8を13/15/20から18/23/29へ増加。同時ごみ上限は40から72、車両上限3は維持します。初期は5棟・9行、拡張購入で10棟・14行へ広がるため、後半の施設と増員に投資できます。詰めて配置しても、拡張前は6棟目を購入できません。

同じ10乱数の自然な収益・購入で比較し、据え置き10体・5施設は全体回収77.8%、拡張20体・10施設は86.9%。厳格判定では前者B8/A2、後者A9/S1。1施設1体案は無料の開始施設を1棟加えてもWave2回収49.6%となり、序盤の導入と後半の成長余地を損なうため採用しませんでした。判定基準と次ランクの達成状況を結果画面で確認できます。

`node tests/balance.mjs` は比較・上限・資源保存を、`node tests/team-capacity.mjs` は土地と20体の枠を、`node tests/results.mjs` は各判定境界と失敗・未処理品を検証します。

## v0.1.8 建設区画・段階価格・焼却熱
